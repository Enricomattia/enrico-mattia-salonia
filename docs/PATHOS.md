# Πathos — Project handoff for Codex

_Last checked against the implementation: 28 October 2026._

## 1. What Πathos is

**Πathos** is a personal cultural diary/archive for experiences with **books, films, television, theatre, videogames, albums, concerts, exhibitions, podcasts, opera and other media**. Its purpose is to remember *what* was experienced, *when*, *how it was judged*, and *why it mattered*: dates, ratings, reviews, favourite works, quotations/passages, editions and contextual notes. It is not intended to be an attention-driven social network.

Its author had previously tracked books in **The StoryGraph** and films in **Letterboxd**; Πathos was created to unify these records and cover media those services handle poorly. It started as a single local HTML app, then evolved into an online owner archive and a separate, installable, offline-first app other people can use.

The branding is **Πathos**, with an uppercase Greek Pi. Keep the UI understated, personal, quick to use, and visually consistent with the existing site. The user has repeatedly preferred **removing unnecessary interface copy and decoration** over adding more.

## 2. Two distinct applications — already published

| | Owner's hosted Πathos | Πathos Personal |
| --- | --- | --- |
| Live entry point | <https://enricomattiasalonia.com/pathos> | <https://enricomattiasalonia.com/pathos-personal/> |
| Purpose | The owner's personal archive, viewable by friends | Anybody's independent cultural diary |
| Storage | Supabase (cloud) | IndexedDB on the local device/browser profile |
| Account | Owner signs in to edit | **No account** |
| Public access | Visitors can read only published entries | Not shared/published; local to the device |
| Installation | Ordinary website | PWA manifest, installable standalone window |
| Offline | Do not assume offline editing/sync | Offline app shell; locally saved records |
| Updates | Site deploy | Service-worker update banner and app reload |

Both applications are in the **same GitHub repository** alongside the owner's personal website. They are separate entry points and **must not be combined accidentally**. In particular, never populate Πathos Personal with the owner's archive. Local data is scoped to a web origin/browser profile and storage key, **not globally synchronized**. Installing on another device starts with another local archive. Preview deployments and the production domain also have different browser storage.

`/pathos` and `/pathos-personal/` were deliberately left **unlinked from the main website navigation**. The Next.js routes use `noindex` metadata; the hosted app HTML also has `noindex` directives. This makes the routes unlisted, **not access-controlled**: the owner wants to be able to give a direct link to friends.

Current layout notes:

- Owner route uses a same-origin `iframe` occupying the full dynamic viewport (`100dvh`). The academic-site header is hidden on `/pathos`, and the academic-site footer is hidden on Πathos routes only; the site's other pages retain their header, footer and navigation. The Πathos header remains inside its app.
- Hosted `sync.js` uses the Supabase JS browser client and a public `PATHOS_CONFIG`. Check the actual auth and save flow before any changes.
- The personal app opens the IndexedDB database `pathos-personal`, stores the archive in an `archives` object store under the key `personal`, and maintains an in-memory copy while queuing writes. **Do not rename or clear this storage without a tested migration.** The source includes a `schemaVersion` field for the archive.
- `public/pathos/cover-accent.mjs` and the identical standalone copy in `public/pathos-personal/` provide presentation-only artwork colors. Each app loads its own copy; Personal caches its copy in the staged shell. Keep the copies identical. They never write to the archive, IndexedDB or local storage.
- `public/pathos/book-catalogue.mjs` and its identical Personal copy normalize public Open Library/Google Books metadata, validate ISBN checksums, and implement bounded searches/edition pagination. The owner catalogue API reuses the hosted copy with its own bounded server fetch. Keep both copies identical. They have no archive/storage/session access.
- `review-format.js`, `review-format.css` and `markdown-it.min.js` under each app provide review editing and safe Markdown rendering. Keep both sets identical with `npm run sync:pathos-review-assets`. The vendored parser is reproduced from the exact development dependency `markdown-it@15.0.3`; its MIT license is included beside each bundle. These assets are local and Personal precaches all three; formatting requires no network or storage migration.
- The PWA manifest uses `display: standalone`. The personal service worker caches the offline app shell and eligible remote cover images; remote metadata requests are still network-dependent.
- Both interfaces share conceptual functionality, but are presently **separate copies of the UI code**. A future shared-core refactor has been discussed but not undertaken.

Release changes in PR #6 (`codex/pathos-reliability`):

- Personal keeps the same IndexedDB version, store and `personal` archive key. Each save compares the stored archive with the last successful read/write **inside the same read/write transaction**. A stale window cannot overwrite newer records; its in-memory changes remain exportable. Export those changes and reload to resume editing against the current archive. An older app window without this check must be closed/reloaded after updating.
- JSON restore validates the supported schema version, unique work/experience IDs, work references, text fields, edition fields and passages before migrating a clone. It asks before replacement. Personal atomically stores the previous archive at `archives['before-restore']` with the replacement. **Undo last restore** survives reload and swaps archives with confirmation. Only the most recent pre-restore copy is retained; it is device-local and does not replace external backups. A failed restore transaction preserves both the current archive and the previous recovery copy.
- Hosted restore downloads a recovery JSON file and requires confirmation before replacing the online archive, including publication settings. Keep the downloaded file. Recovery is not silently persisted as a private archive in browser storage.
- Hosted saves use a fresh owner-session check, an archive comparison against the latest cloud read, and a same-origin Web Lock where available. This rejects previously saved changes from other windows/devices, but **is not an atomic cross-device conditional write**. A simultaneous save on another device (or from an old client) can still race the preflight read; resolving that needs a separately reviewed server-side revision check.
- Automatic ISBN enrichment fills missing edition fields and preserves recorded metadata, identifiers and uploaded/manual covers. Editing an edition also preserves its contributors.
- Save errors remain visible and block Personal updates; a later successful write clears the failure. Personal refuses updates/restores while an entry dialog, import or metadata operation is open/running, and prevents new edits while preparing an update. Unsaved form entries are not auto-saved.
- The service worker uses shell cache `pathos-personal-shell-v25` and looks up shell assets in its own versioned cache, so a waiting release's cache cannot be served prematurely. The standalone manifest is unchanged. Preview v4/v5 provided the real reliability update-cycle check; v6 stages interface simplifications and v7 adds official-page image suggestions. Release v8 adds winding timelines, mobile layout improvements and Current above the Home timeline. The v9 follow-up makes both timelines vertical and nearly full-width on phones (600px and narrower), retaining winding rows on larger screens. Release v10 adds viewing language and publication series and promotes Timeline into the primary navigation. Release v11 adds restrained artwork-derived accents and caches the standalone accent module. Release v12 improves accent recovery and the visibility of pale colors. Release v13 caches the book catalogue module and extends the existing bounded, best-effort cover cache to Google Books artwork.

## 4. What the user wants the experience to feel like

### Core areas

The v0.6 redesign (15 October 2026, requested by the owner from a design canvas of seven proposals) replaced the winding timelines, the separate Timeline page and the old Insights layout. It is presentation only: no storage, edition, publication or authentication behavior changed.

- **Type:** Newsreader (serif) for titles, reviews and passages; Instrument Sans for controls. Both are self-hosted WOFF2 subsets under `public/pathos/fonts/` and `public/pathos-personal/fonts/` (identical copies, SIL OFL; see `LICENSE.txt`). Personal precaches them in its shell so the type works offline. The Greek Π keeps its Times New Roman fallback.
- **Home is the diary:** **Current** (in-progress experiences) sits on the left and the cover-only **Favourites** shelf on the right in one top row above 850px. At 850px and narrower they stack in that same reading order. Each section uses the full row when the other is empty; when both are empty the row disappears. Favourites apply to the whole work (`work.liked`), with one cover per work using its latest recorded edition. The shelf scrolls within its row on phones, hides when empty, and opens the work reading page. Hosted favourites are public for works with at least one published experience. The public RPC projects only the boolean `liked`; private-only works remain excluded, and ownership stays private. Below these, every dated, non-planned experience is listed newest first and grouped by month. The 17 October follow-up restores the winding snake within each month: three columns above 1100px, two from 601–1100px, and a vertical thread on phones. Alternating rows reverse visually; DOM, keyboard and screen-reader order remain chronological. Each stop shows its own day and weekday, including experiences on the same day. Cards retain the new serif titles, exact-rating pips, reading-page navigation and two-line review excerpts; reviewless cards omit the excerpt. Each card has a restrained tint and edge from its recorded edition cover (then the work cover), with a deterministic title/creator tint when artwork cannot supply a colour. The colour is decorative and never writes metadata or substitutes an edition. A decorative SVG connects desktop rows; resize, font loading, Home navigation and pagination recalculate its geometry. There is no horizontal panning. The first 60 entries render immediately; **Show earlier entries** adds 100 at a time and moves focus to the first new entry. The list keeps `#timelineList`, and `showView('timeline')` opens Home.
- **Navigation:** four pages, in this order: Home / Library / Passages / Insights. Metadata & covers and Import & backup sit behind one sliders icon in the header (`#settingsMenu`, editor-only), which closes on an outside click or Escape. Measured overflow still exists as a fallback: with unusually large text, Passages, Insights and then Library move into **More**, while Home stays inline. Guests never gain editor-only links.
- **Experience pages:** selecting an experience anywhere (diary, Current, Passages, Insights drill-downs, longest reviews) opens its **work page**, not the edit form. The page has a header band tinted with the cover's accent colour: a large cover, title, creator/year and the work's **presentation passage as an epigraph**. Below it, every experience follows, newest first, each with its date, status, rating, edition, the review set as reading text and passages as pull quotes. Opening from a specific experience scrolls to it. **Edit** (editor-only) on each experience opens the existing form; `openExperience(id)` remains the edit entry point and `openExperiencePage(id)` the reading one. Log again and Favourite stay in the header. The entry form also has a visible Favourite checkbox. Book reading pages omit the Open Library work link, ISBN/EAN/catalogue identifiers, identifier links and import-source labels; these remain recorded in metadata and backups. On sign-out an open work page closes.
- **Ratings** appear as five pips plus the exact value (e.g. `1.75/5`); quarter values show a half pip.
- **Typographic covers:** when a work has no artwork, or the image fails to load, a cover is drawn from the title and creator (a muted band whose colour is derived from the title, plus Π). It is presentation only: nothing is saved, and no edition is implied. Small covers show only the band.
- **Library:** medium chips (All plus each medium present) replace the media select; status, content filters and sort are unchanged. Cards use serif titles and pips, and show an experience count only when there is more than one.
- **Insights:** a period switch (current year / All time) defaults to the current year once it has a dated experience. A small 24px serif line shows only the experience count ("73 experiences"), followed by one row of stats (average rating, ratings, written reviews, words of review, rated five). In year mode, **The year in covers** shows each month's covers (selectable). The rating chart has fixed half-step columns; quarter ratings are counted in the nearest half column, and the note says how many were grouped (records keep exact values; the drill-down uses the same grouping). Experiences by year and Average rating by year appear only in All time. All drill-downs respect the selected period.
- **Phones (600px and narrower):** the page list becomes a fixed bottom bar with icons and labels and, for editors, a round **Log** button in the middle (it replaces the header's Add button). Touch targets are at least 44px, and the page and dialogs fit the width. The work page is full-screen. Current scrolls sideways within its own row, and Library chips scroll within theirs. Inputs keep 16px text. Personal still hides ready-status and Install controls in standalone mode while showing save errors.

Work details show each experience's review once, with no duplicate Latest review summary or experience/review count chips. A single experience is the standard display; repeat experiences retain their separate dates, editions and reviews. A discreet Log again action still opens the repeat-experience form. Library cards show an experience count only when there is more than one.

Book entry forms use one editable **Language** field and one **Publisher** field for edition filtering and recording. Choosing an edition fills it; looking up an ISBN does not erase a manually recorded language before selection. **I own this book** appears in the main form only for books and records optional boolean `work.owned` under schema version 6. Existing StoryGraph ownership in `work.sourceMetadata.owned` or experience `details.owned` is recognised for display; explicit `work.owned` takes precedence, including false. There is no automatic rewrite or storage migration. Ownership and favourites survive repeat logging, unrelated edits and JSON backups; Cancel does not change them. Public hosted responses include the explicitly requested favourite flag for published works and continue to omit ownership.

### Review formatting

Both entry forms show formatting directly inside the review being edited. Bold, italic, strikethrough, quote, bullet list, numbered list and link buttons apply to a selection or the text typed next. Toolbar buttons show the current formatting. Ctrl/Cmd+B, I and K format bold, italic and links; Ctrl/Cmd+Z and Shift+Z undo/redo. Enter continues a list and an empty item exits it; Shift+Enter adds a line break. Links use a small inline address control with Apply, Remove link and Cancel. The separate Preview toggle and visible Markdown textarea are replaced by one visual writing surface. Pasted text stays literal; pasted HTML is restricted to the supported text formats and safe HTTP(S) links, with no image or executable embeds.

The editor uses a locally bundled ProseMirror document model, selection and history. `src/lib/pathos-review-editor.mjs` is the source; `scripts/pathos-review-editor.cjs` reproduces the identical `review-editor.js` bundles and dependency notices in both apps. Run `npm run sync:pathos-review-assets` after source/dependency changes. The editor shares the reader's Markdown tokens and schema, and serializes changed reviews into the existing hidden `name="review"` field for the unchanged save flow. Opening an entry, selecting text, cancelling, saving unrelated fields and undoing back to the original document preserve its exact original review string, including whitespace. No review is bulk-rewritten. If an editor bundle fails to load, the original text field stays available.

Reviews remain strings in `experience.review` under schema version 6. Existing strings, IDs, editions, publication settings, backups, imports and storage keys are retained without a bulk rewrite. Recognized Markdown in existing reviews now displays as formatting; ordinary line breaks and paragraphs remain readable. Home/Insights excerpts, Library review search and word counts use the rendered text, excluding formatting markers and link destinations. Work pages use a block container for paragraphs, lists and quotations. Raw HTML is escaped, images are disabled, and explicit links accept only HTTP(S), opening with `noopener noreferrer`. No scripts, HTML embeds or automatic image fetches are enabled by review content. StoryGraph's existing HTML-to-text import cleanup is unchanged.

Personal shell **v25** stages the direct editor and its CSS/parser through the existing Update / Later flow, retaining the same IndexedDB database and records. The manifest and hosted/public authorization boundary are unchanged. The v24 → v25 regression harness serves each release's own formatting assets, so a waiting release cannot change the running editor.

### Owner-only discovery and free local matching

The signed-in hosted owner has a **Find a work** action. Search books (Open Library plus optional Google Books) or films (TMDB), open a preview without adding anything, then optionally open **Add to Planned** or **Log experience**. Book search has language/publisher filters and More results. Only the existing form's Save writes records. Open Library previews represent works; Google Books previews represent editions. Generic work covers never fill an exact-edition cover. Logging a new work opens the existing edition picker with the edition unselected, including Google Books suggestions. Existing works retain their recorded editions. Current remains above the Home timeline; public navigation and Personal's local-only storage are unchanged.

`/api/pathos/catalogue` requires a bearer access token, verifies it through Supabase Auth's `/auth/v1/user` and compares the returned user ID to the fixed owner. The three public configuration identifiers match `public/pathos/config.js`; a test detects drift. Browser flags and publishable keys do not authorize calls. Cross-site requests are rejected. Searches and details fetch fixed Open Library/Google Books/TMDB endpoints with bounded bodies/timeouts, no redirects and a two-lookup concurrency cap. Auth tokens go only to Supabase. The existing device-local TMDB read token is sent in `X-Pathos-TMDB` and forwarded only to TMDB; optionally configure `PATHOS_TMDB_TOKEN` on the server. A device Google key is sent in `X-Pathos-Google-Books`, forwarded only to Google's fixed Books API with the verified site's origin as Referer; alternatively configure `PATHOS_GOOGLE_BOOKS_KEY` for discovery on the server. No keys appear in responses, saved covers or archive exports. No OpenAI key or paid AI endpoint is used. Film search still needs that free non-commercial TMDB token; missing setup is explained in the UI. No database/RLS/schema changes.

The owner explicitly requested **free** matching, so the initial OpenAI API proposal was replaced with a local content-based recommender. Enabling matching downloads the pinned Transformers.js 3.8.1 runtime and `Xenova/paraphrase-multilingual-MiniLM-L12-v2` q8 weights, revision `2c4055b12046f11709e9df2c122e59ffbdc2f900` (about 118 MB weights, plus tokenizer/runtime). Model assets may be browser-cached. Inference runs in a Web Worker, without sending history to an AI service or incurring AI API charges. Searches still disclose the search query to their catalogue providers. Existing hosting/catalogue quotas remain applicable.

Every eligible non-planned past experience contributes a local representation using metadata, tags and a bounded review excerpt. Target-work experiences are excluded to avoid scoring a book against its own review. Review excerpts are chunked for the small encoder context; all eligible experiences are considered, while very long reviews are truncated. Cosine/subject/creator similarity identifies related works across media, then explicit ratings relative to the owner's average inform fit. Favourites have a small weight boost; repeat experiences are preserved with reduced per-work influence. Unrated reviews can establish similarity, but are not guessed to be likes/dislikes. The evidence panel shows actual titles, ratings, shared catalogue subjects and review excerpts, including relevant negative evidence. It uses templates rather than generated literary analysis.

Every completed match also prints a short explanation: how the comparable ratings relate to the owner's average, which recorded works support the connection, their actual ratings, shared catalogue subjects and/or creator, plus specific reasons for limited confidence (small rated history, few distinct comparisons or a short/missing description). Evidence cards for rated works come from the same nearest comparisons used in the verdict; unrated connections can fill remaining cards and are labelled **unrated**, without assigning them a like/dislike. One or two rated experiences no longer block matching: the panel explains tentative connections while retaining **Not enough evidence**. With no eligible history it explains the absence of evidence immediately, without downloading the model. The paragraph is assembled locally from those facts; it is not an LLM interpretation of the work or review. Scoring thresholds, privacy and paid-service behavior are unchanged.

**Strong / mixed / weaker match** and **Low / Moderate confidence** are experimental estimates, not calibrated probabilities. Sparse metadata or history produces Not enough evidence. Synthetic positive/negative tests establish functioning, not predictive accuracy on the owner's tastes; held-out-history evaluation and user feedback should precede stronger accuracy claims. The model can be slow or unavailable on some browsers/devices, and failures stay visible. Private embeddings/texts live only in worker memory (bounded session cache); sign-out hides/closes discovery, aborts lookups, clears results and terminates the worker. No private match cache is persisted. All server catalogue calls, including the pre-inference owner check, enforce owner access independently of UI visibility.

### Experience model

- Distinguish a **work** from an **experience of a work**. Re-readings/re-watches can have different dates, ratings, reviews and, for books, editions.
- Media categories include books, film, TV, theatre, videogames, albums, concerts, exhibitions, podcasts, opera and other categories supported by the existing code.
- Useful fields include status (completed/in progress/planned/did not finish), start/end dates, rating, review, passages/quotes, tags, venue, source URL, cover, favourite status and repeat experience.
- Films have optional **Viewing language**, stored as `experience.viewingLanguage`. Record the language actually watched, never infer it from a film's original language. Repeat viewings start with a blank language and retain separate choices. The field appears in work details and is searchable in Library.
- Books have an optional collapsed **Book profile** section: comma-separated **Genres** on the whole work (`work.genres`), **Moods** and **Pace** on each reading (`experience.moods`, `experience.pace`, empty/slow/medium/fast). Catalogue subjects/categories suggest genres; an explicit saved array, including empty, overrides later suggestions/enrichment. Rereadings retain shared genres and start with blank moods/pace. These fields are searchable; work pages show genres in the header and each reading's moods/pace. StoryGraph CSV imports recognise Moods, Pace/Pacing and Genre/Genres when those columns exist. No pace is guessed when absent. Legacy Tags/Moods remain in imported tags for compatibility. Re-importing an unambiguous duplicate can fill only missing profile fields, with matching edition ISBN or source ID; it preserves manually recorded/cleared values, IDs, editions, reviews, passages and tags. Hosted owner JSON stores the optional fields, but the existing public projection does not expose the new profile fields. No public RPC/RLS or visibility changes are included.
- Exact book editions have optional **Publication series** and **Series number**, stored as `edition.series` and `edition.seriesNumber` alongside `edition.publisher`. For example: `Einaudi · Nuovi Coralli n. 15`. The number is text, allowing values such as `2 bis`. Repeat readings retain independent edition choices, and manual series values survive enrichment, edits and backups. These are additive optional fields; schema version 6, IDs and storage keys remain unchanged.
- Add a little **Today** shortcut near date fields; this was a requested UX improvement and should be preserved.
- Dates must remain flexible: users may log an experience on the same day or have incomplete dates; do not reintroduce validation that unnecessarily forces finish after start for every status.
- Keep the interface simple; do not invent new mandatory form fields.

### Metadata and images

**Book catalogue search (v13):** both entry forms search titles, authors or ISBNs across Open Library and, when a device key is configured, Google Books. Each source returns 20 results per page with an explicit More results action. Browser language biases Open Library's best edition/title without excluding other languages; translated result titles retain the original title as an alias. Results with the same title are not collapsed across authors or editions. A provider failure leaves the other provider available and displays a short warning; manual entry remains available. No Goodreads scraping, StoryGraph API, SBN integration, bulk catalogue mirror or automatic archive rewrite is introduced.

The edition picker loads Open Library editions in pages of 100 and displays 30 at a time, with separate Show more / Load more actions. Language/publisher filters apply to the loaded set; Find editions also asks Open Library's search index for its best matching edition of that exact work, which can be outside the first REST page. This index may return only one edition and is not an exhaustive filtered edition catalogue. Additional REST pages remain loadable. Exact ISBN lookup checks both providers, validates ISBN-10/13 checksums, and discards unrelated Google volumes. Equivalent ISBN-10/13 records merge only when reported publisher, language, year and format do not conflict; conflicting records remain explicit choices. Search and ISBN lookup never fill edition fields until the user chooses a result. Automatic enrichment fills gaps only from a single unambiguous ISBN result; existing metadata and manual/uploaded covers survive. A generic work cover is not substituted for a recorded edition. Closing/changing the form cancels pending lookup results.

Google Books volume identity is stored as optional `work.external.googleBooks` and `edition.googleBooksId`, with optional edition `title` and `sourceUrl`. Edition IDs and source links survive edits, JSON backups/restores and offline reloads; old archives keep schema version 6 and existing storage/IDs. A volume's publication date belongs to the edition and is not asserted to be the work's original year. The local match history excludes a recorded Google volume's entire work, including repeat readings.

**Exact-ISBN fallback (v19):** when the existing sources provide no edition, both entry forms automatically try Hoepli through `/api/pathos/isbn-fallback`. This covers ISBN searches, the exact-edition picker and the existing gap-filling metadata enrichment. Title/author searches and hosted Find a work discovery retain their existing sources. No StoryGraph fetching is enabled. The fallback accepts only a checksummed ISBN, sends no archive/auth/cookies/keys, and fetches only HTTPS `www.hoepli.it` search/product paths for that ISBN. Normal redirects and product links are revalidated, with at most four requests, eight seconds and 2 MiB per page; no challenge bypass or bulk indexing. A JSON-LD Book must explicitly report the requested ISBN; URL/title similarity is insufficient. HTTP blocks/errors leave manual entry available. The public same-origin JSON POST route limits input to 256 bytes, rejects cross-site requests and extra keys, allows two concurrent lookups, and bounds its metadata-only cache to 200 entries (hits 24h, misses 10m). Responses are no-store/noindex. This endpoint is online metadata lookup shared with Personal, not archive sync.

The reported publisher, language, publication year, format, series, translator and printing (`edition.printing`) are preserved, along with `source: 'Hoepli'` and the exact product `sourceUrl`. Preliminary Roman pages stay separate, e.g. **LIII + 87**. Page-count and printing conflicts remain distinct candidates. Artwork is accepted only from Hoepli's HTTPS image hosts, never substituted by an unrelated work cover. Search/picker results still require explicit selection; metadata enrichment only fills empty fields. On 17 October 2026 the real endpoint returned ISBN **9788811361190**, Garzanti, Italian, 2008, 18ª, I GRANDI LIBRI, Buttafava G., LIII + 87. This validates one provider/example, not comprehensive Italian edition coverage. The Personal worker caches `copertine.hoepli.it` covers best-effort after loading; offline records and uploaded covers remain local. StoryGraph moods/pace are currently available through CSV/manual entry, not automatic live page enrichment.

**Google setup:** under Metadata & covers → Catalogue access (inside More when space is limited), follow the Google Books key link, create a Google Cloud project/API key and enable Books API, then restrict it to Books API and the web origins you use (production and preview need their respective referrer permissions). Paste the key into the optional field and Save; clear and Save to remove it. It is stored at `localStorage['culturalArchive.googleBooksKey']` on that origin/browser, outside backups. Personal and hosted forms call Open Library/Google Books directly; Hoepli fallback uses the same-origin ISBN-only route. No archive is sent to that route. Owner discovery uses its authenticated same-origin API. Queries go to configured providers, never reviews or passages. Google quotas/restrictions apply; errors leave Open Library/manual entry usable. A server-only key enables hosted discovery, not direct Personal/form requests. No live Google key was available during implementation; real Google credentials/referrer restrictions remain a setup verification step. Official references: [Google Books API keys](https://developers.google.com/books/docs/v1/using#APIKey), [Open Library search](https://openlibrary.org/dev/docs/api/search).

- Books: prioritize **correct edition** (language, publisher, cover, year, format). Existing manual edition editing supports **ISBN, EAN/barcode, StoryGraph UID and other identifiers**, plus hand-uploaded covers. Matching the *wrong* edition is worse than having no cover. In particular, a generic Open Library cover does not establish exact edition identity.
- Films: metadata/cover enrichment through TMDB where already implemented. Keep any user-supplied API credential out of commits.
- Other cultural works: the entry form's More details section has **Find image** beside the reference/event URL for theatre, concerts, exhibitions, opera and other non-book/non-TMDB media. Pasting/changing an event link suggests images when the cover is blank or contains that same webpage URL. Opening an existing entry with the same page URL in both fields also suggests images; this handles the current KA-IN record without silently changing it. Existing image covers are not looked up automatically. Choose **Use image**, then **Save**; cancelling or merely loading suggestions never changes the archive. Replacing a different existing cover requires confirmation. Manual cover URLs remain available.
- Image suggestions come from `/api/pathos/page-images`, an online, same-origin Next.js Node route shared by both interfaces. It receives only the requested public URL, not the archive, IDs, reviews or credentials. It considers Open Graph, Twitter cards, JSON-LD images and ordinary/lazy page images, resolves relative URLs, deduplicates candidates and excludes obvious logos/icons and organization-logo metadata. It returns at most six choices, never an automatic saved cover. On the real KA-IN page, two production photos were found; its organization metadata incorrectly points to unrelated DARDUST artwork, which is excluded. Books keep their exact-edition workflow; Film/TV keep TMDB.
- The fetcher accepts ordinary public HTTP(S) URLs only (no credentials/custom ports), rejects nonpublic IPv4/IPv6 and mixed DNS answers, pins a validated address for the connection, rechecks each redirect (maximum three), limits HTML to 2 MiB and lookup time to eight seconds, and forwards no cookies/auth headers. Candidate image hosts are also checked. The route limits input size/concurrency, refuses cross-site browser requests and marks responses no-store/noindex. Discovery is metadata lookup. The same endpoint accepts `mode: store` to copy selected public raster artwork (PNG/JPEG/WebP/GIF/AVIF) with pinned DNS, validated redirects, no credentials, signature checks, an 8 MiB limit and an eight-second deadline. SVG/HTML are refused. The browser decodes and compresses it to at most 600 × 900 JPEG before Save. Some sites may block downloading; failure leaves the current cover intact.
- Cover images from external services may not load when offline unless cached. Event-image selections are copied into the form as compressed JPEG data URLs before Save. Saving an existing non-book/non-TMDB remote image also copies it, except when its URL is the reference webpage itself (choose an image first). A failed download leaves the form and archive intact and asks for an upload or retry; existing remote records are not bulk-rewritten. Image lookup requires a connection, while local records and JSON backup/restore continue to work offline. Uploaded local images should be preserved in backups.

## 5. Cloud data and privacy — hosted owner's Πathos

The owner authenticates through Supabase email/password. Site visitors who are not signed in can see only published experiences and safe fields. New hosted experiences are **public by default**, including entries logged again, discovery/planned entries and CSV imports. The entry form has a visible **Keep this experience private** checkbox, applying to its review and passages too. Explicit `isPublic: false` remains private. Editing a legacy entry with a false/missing flag keeps it private; existing archives and JSON restores retain their recorded visibility without bulk changes. Personal remains local-only with no publication controls.

The public RPC's explicit projection includes optional `viewingLanguage`; publication series travels in the already-projected `edition` object. `scripts/pathos-public-viewing-language.sql` adds only that one safe field to the inspected function and includes a rollback that removes its public projection without deleting stored languages. It preserves the owner/publication filter, permissions, RLS and private archive write function. The database's fallback for malformed/missing publication settings remains private; new-entry defaults are applied by the hosted UI, never by migrating old records.

The Supabase implementation uses:

- `public.pathos_works`: work documents (`JSONB`) scoped to owner.
- `public.pathos_experiences`: experience documents (`JSONB`) with a public visibility flag.
- `pathos_get_my_archive()`: authenticated owner's full archive.
- `pathos_get_public_archive(p_owner_id)`: intentionally public RPC returning only published data/allowed fields.
- `pathos_replace_my_archive(p_archive)`: writes the owner's archive, behind authorization/RLS controls.

Tables have row-level security. The public RPC is deliberately usable by anonymous visitors, but **must never reveal unpublished records or fields**. Before editing database functions or policies, retrieve and inspect their current definitions and existing production data. Test public reads while signed out, authenticated owner reads/writes and unauthorized writes separately. Never put `service_role`, passwords, database connection strings or raw archive dumps into GitHub. The Supabase URL and publishable key in `public/pathos/config.js` are *public* identifiers and **must not be treated as a security boundary**.

The owner requested the new public default on 15 October 2026. Preserve existing visibility in any future changes; do not bulk-toggle an archive without explicit authorization.

## 6. Local data and updates — Πathos Personal

The personal version is **local-only** by deliberate design. Friends download/install the PWA, add their own works and experiences, and keep the data on that browser profile/device. It includes JSON export/restore and existing import workflows (including StoryGraph and Letterboxd, as supported by the checked-in implementation). They should back up regularly; deleting site data or changing devices **will not magically recover their archive**.

The PWA's current update architecture:

1. The browser registers `/pathos-personal/sw.js` with scope `/pathos-personal/`.
2. A new worker downloads/caches the next app shell and **waits** rather than immediately taking over.
3. The app notices a waiting worker and offers a small **“A new version of Πathos is available”** banner, with **Update** and **Later**.
4. Update checks occur on app launch and at intervals/when focus or connectivity returns, subject to browser availability.
5. Clicking **Update** waits for pending IndexedDB writes. A failed save blocks the reload; the user is prompted to export a backup.
6. The app messages the worker with `SKIP_WAITING`; when the new worker becomes controller, the app reloads.
7. The local IndexedDB archive is not part of the service-worker cache and should survive normal updates.
